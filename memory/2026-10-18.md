# 2026-10-18：搜尋不相干 ＋ 查核召回漏找（兩問題都存在，已修待回歸）

主題：用戶回報兩件事——(a) 網路搜尋結果與新聞不相干、(b) 查核源明明有對應條目卻檢索不到。
本日把兩條路徑都做了根因定位、修正、與離線/線上驗證。

## (a) 網路搜尋「不相干」：根因三條

1. **入口炸掉（工作區未提交的改動引入）**：`web_search_client.search()` 對未定義的
   `_serper` 取值 → `NameError`，呼叫端 `except` 吞掉 → 搜尋整條回空。
   HEAD（a83a462）版沒有這問題 → 是上一 session 未提交改動的 regression。
   修：快源並行表 `_QUICK_SOURCES`（名稱→呼叫），不再有「submit 了卻沒 result()」的懸空 future。
2. **Bing 直爬回傳 decoy**：`search_bing`（free-search 服務）未過濾。實測 48 筆結果
   與新聞標題的 SBERT 吻合度（門檻 0.45）：**0% 過門檻、中位 sim 0.019**；
   樣本是 Netflix 土耳其官網、Lidl 購物、希臘動物園、雙陸棋站等完全無關頁面。
3. **Google News RSS 是 wrapper**：`news.google.com/rss/articles/...` 抽不到正文；
   Google cookie/CSE 全 0 筆（CSE 403）。→ 併入池子只會稀釋。

修法與驗證（`scripts/probe_web_search_ab.py`，A/B 同一批新聞標題）：
- 新增 `search_bing_news()`：Bing News RSS（`format=rss&setlang=zh-Hant&cc=TW`），
  真實媒體直連＋130-200 字摘要 → 實測 **41 筆、95% 過 0.45、中位 sim 0.650**。
- `_is_relevant_to_query()`：query-relevance 過濾（decoy 直接丟）。
- `_resolve_google_goto()`：解 `/goto?url=` 302 → 真實網址。
- 合併順序改「證據可用度」：cookie > cse > bing_news > bing > ddg > google_news(wrapper)。
- A/B 對照：`old_bing` 0%（48 筆）vs `new_bing_news` 95%（41 筆）vs `new.search()` 95%（44 筆）。
  明細 `/tmp/opencode/web_search_ab.jsonl`。

## (b) 查核「有卻找不到」：根因六條

1. **召回參數**：moreLikeThis 預設 `minimumShouldMatch` 對長改寫文回 0 筆。
   實測同一 258 字查詢：`default msm → edges=0`、`msm10% + first=25 → 25 edges`。
2. **每查詢只取 2 nodes** → 正確條目排在同主題噪音後就撈不到。
3. **門控語意 bug（per-text vs cross-text）**：舊碼三層各自 `any(文本)`：
   `any(entity) and any(kw) and any(num)`。F12 實測：轉傳原文過關鍵詞、查核回覆文過數字
   → 2018 年真查核（0.6元/84元）被判與 2026 捏造文（800元/50元）同事件，sim 0.763
   硬命中（≥0.72）**不經 LLM 直接採信**。
4. **比對文本選錯**：`inaccurate/partial` 比謠言原文是對的，但 `accurate` 條目（＝回覆在
   查證新聞）拿轉傳原文比 → 口語開場跟新聞沒交集（R04 國防部戰備飲用水被誤擋）。
5. **日文站無語言閘門**：中文新聞撞日文查核（sim 0.509-0.616 假命中，R09/R17/B09/B17）。
6. **負快取永不過期**：`multifc_cache.db` 9179 筆 `not_found`（最舊 52 天）、
   `cofacts_cache.db` 675 筆；`_mcache_get`/`_cache_get` 有 ts 欄但不讀 → 一次失敗永久查不到。

修法：
- 三檔 msm 召回（`_RECALL_PASSES`：10%/first25、20%/first15、30%/first10）＋
  `_RECALL_MAX_NODES=40`＋召回預算 `COFACTS_RECALL_BUDGET`（預設 25s）＋連續兩次失敗中止
  （Cloudflare 403 防護）。
- `_pick_sim_text()` 文本分流；`_gate_texts()`＝{轉傳原文、狀態感知回覆文}；
  `_gate_pass()`＝**同一份文本**三層（entity ∧ kw ∧ num）全過、任一文本過即放行。
- 關鍵詞視窗放大：q 500 / c 1200 字（原 300/400 只看得到開場白）。
- `_numeric_gate()` 數字指紋閘門，**預設 strictd**（含日期的嚴格模式）。選它的依據：
  60 筆離線矩陣（`scripts/eval_numeric_gate.py`）——raw/off REAL 11、FAKE 硬命中 2；
  union/off REAL 13、硬命中 3；**union/strictd REAL 13、硬命中 0**。
- jfc/infact 語言閘門（`_detect_lang(text) != "ja"` → 放空）；快取 TTL 負 6h / 正 7d；
  jfc3:/infact3: 前綴升版作廢舊快取。

驗證：
- `scripts/test_cofacts_recall_contract.py`：**ALL PASS（32 checks）**，含新增 [6] 門控堆疊
  （per-text AND、strictd 預設、soft/strictd 對零數字指紋候選的差異）。
- `python/calib_gate.py`：關鍵詞 4 對（3 字/交集 1 全對）＋ 數字堆疊 5 對
  （F12/F17 應擋、R03/R04/R15 應放）在 **strictd 全 OK**（off/soft/strict/softd 會 MISS）。

跑完後又抓到並修掉三個真 bug：
1. **千分位正規化**——`"6,000元"` 的逗號沒被去掉（Python `\b` 認 CJK 為 word char → `(?=\d{3}\b)` 在「000元」前不成立），指紋變 `6,000元` 對不上 `6000元` → 數字閘門把 R06 的正確命中（0.871）誤擋成 not_found。修法：`(?=\d{3}(?!\d))`。dump4（修正後）才看到 REAL 20/20。
2. **多源查核（MyGoPen / 蘭姆酒吐司 / HKBU）缺門控＋跨源軟命中搭便車（D1）**——
   - `factcheck_multi.py` 原本對中文標題型站台只看 `sim >= 0.50`，沒跑實體／關鍵詞交集／數字門控 → R09（疾管署估8月中新冠高峰）撞上 MyGoPen「網傳新冠又來了？這5種症狀要當心？」（sim 0.6037），B14（機車零違規抽獎）撞上 MyGoPen「機車未打方向燈罰1200」（sim 0.5878）。
   - 更致命的是 `orthogonal_scorer.compute_d1_evidence_verdict`：當 Cofacts 有 `0.926 accurate` 硬命中時，LLM 因 Cofacts 正命而判 `full_body_evidence`，結果 MyGoPen 的 `0.6037` 軟命中搭 `deep_full=True` 便車進 `valid_hits`，再靠 `_sev_key` 的嚴重度優先順序把 `0.926 accurate` 壓死，導致 R09 真新聞被鎖在 21.1 分（舊 60 筆評測唯一的 MISS）！
   - 修法：(a) `factcheck_multi._title_gate_and_sim` 對齊三層門控（softd）並升版快取前綴 `m4:`/`hkbu2:`/`rt2:`；(b) `compute_d1_evidence_verdict` 在有硬命中（≥0.72）時剔除其他來源軟命中（<0.72）；(c) 當 Cofacts `NOT_RUMOR`（accurate）實為「闢謠澄清文」（如檸檬水案 `2i9uu0bit7kta`：「目前沒有任何研究證明喝熱檸檬水可以抗癌」），LLM 讀完判 `full_body_evidence` 且 `credibility_score <= 30` 時，將蘊涵方向反轉為 `inaccurate`（refutes）。實測 R09 21.1→**90.5（supports）**、B14 48.3→**60.0（supports+釣魚上限）**、`real_fake` **13.55（refutes，直接由 Cofacts 檸檬水查核觸發）**。
3. **`_get_sbert()` 執行緒鎖**：`get_all_fact_checks` 8 執行緒並行首次惰性載入 SBERT 時無鎖會卡死，已加 `_SBERT_LOCK`。

## 已知殘留／代價（誠實記錄）
- strictd 的代價：FAKE 被查核判「不實」的筆數從 6 降到 3（F01/F02/F05/F19 改走其他維度）、
  BAIT 少數真命中（B19）被丟。方向是刻意選的：**寧可少一個「假新聞被標不實」，
  也不要一個「假新聞被標屬實且不經 LLM 直接採信」**。
- 召回有 run-to-run 波動：同一生產重放，B13/B14/B15 曾瞬時 not_found（~8.9s），
  但單筆複驗全部恢復（0.914/0.935/0.790）。判定：API/msm ranking 波動，非閘門問題。

  已加召回預算 25s＋連續兩次失敗中止；驗證時不要與其他 Cofacts 探測併行。
